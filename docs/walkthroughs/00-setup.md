# 00 — Setup

> **Milestones:** cross-cutting · **Status:** done · **Next:** [01 — Baseline and quality gates](01-baseline-and-quality-gates.md)

Everything every other walkthrough assumes: the tools on your machine, the development secrets, the three Compose services (Postgres, Valkey, Mailpit), a migrated development database and a migrated test database, the first administrator, the API running on port 8731, a Postman collection that carries the session cookies, pgAdmin connections, and the automated checks. Do it once; come back to [S0.14 Troubleshooting](#s014-troubleshooting) when something stops working.

## What this phase delivers

- A local stack: the API on the host (`uv run uvicorn …`, http://127.0.0.1:8731), and in Docker Compose: `postgres:18-alpine` on `127.0.0.1:55432`, `valkey/valkey:8-alpine` on `127.0.0.1:56379`, `axllent/mailpit:v1.27` with SMTP on `127.0.0.1:51025` and its inbox on http://127.0.0.1:58025.
- Development secrets in `secrets/` (for Compose) and a matching `services/api/.env` (for the API), both git-ignored and generated by `scripts/dev_secrets.py`.
- Two databases with identical grants: `humani_t` for development data and `humani_t_test` for the Postgres contract tests.
- An administrator account, created from the command line.
- A Postman collection that captures the `__Host-session` and `__Host-csrf` cookies into variables and sends the `X-CSRF-Token` header.
- pgAdmin connections as the superuser and as the app's own role.
- The full set of automated checks, with and without Postgres and Valkey.

## Architecture choices and why

### D0.1 The development stack now, the production shape later

- **Decision:** in development, the API runs on the host with uv and `--reload`; only the backing services run in Compose, each published on `127.0.0.1` only. The production shape (milestone M4) puts everything in Compose behind Caddy.
- **Today:**

```text
your machine
├── uvicorn (the API, run with uv)          http://127.0.0.1:8731
└── Docker Compose
    ├── postgres:18-alpine                  127.0.0.1:55432
    ├── valkey/valkey:8-alpine              127.0.0.1:56379
    └── axllent/mailpit:v1.27               SMTP 127.0.0.1:51025, inbox http://127.0.0.1:58025
```

- **Target (M4, production self-hosting):**

```text
internet ─► caddy (HTTPS, serves the web app, proxies /api)
               └─► api (FastAPI) ─► postgres, valkey
                   worker (background jobs, scheduled purge and audit checks)
                   migrate (one-shot, runs Alembic as the schema owner)
```

- **Why:** an edit-reload loop on the host is fast, while Compose pins the exact Postgres, Valkey and Mailpit versions everyone runs. In production only Caddy will publish a port; every other service stays on an internal network.
- **Rejected:** containerising the API before a Dockerfile exists (slower loop, nothing gained yet); installing Postgres and Valkey natively (versions drift between machines).
- **Costs:** development is plain HTTP while the cookies are `Secure`, so Postman needs the manual cookie header in [S0.10](#s010-postman); the development topology is not the production one (that is [`compose.yaml`](../../compose.yaml), [14](14-deploy-and-ci.md)).
- **Where:** [`compose.dev.yaml`](../../compose.dev.yaml).

### D0.2 Secrets generated locally, written once, never committed

- **Decision:** `python scripts/dev_secrets.py` writes random passwords (`db_superuser_password`, `db_migrator_password`, `db_app_password`, `valkey_password`) and a key-encryption key (`key_encryption_keys`, as `1:<base64>`) into `secrets/`, and a `services/api/.env` that points the API at them. It never overwrites an existing file, so re-running it is safe; deleting a file and re-running rotates that one value. Compose passes the passwords to containers as Docker **secrets** (files mounted at `/run/secrets`), not environment variables.
- **Why:** nothing secret is ever in the repository (`.gitignore` covers `.env`, `.env.*` except `.env.example`, and `secrets/`), and environment variables leak into process listings and crash reports where secret files do not.
- **Rejected:** committed example passwords; passwords in Compose `environment:` blocks.
- **Costs:** Postgres creates its roles only when the volume is first created (`infrastructure/postgres/init/01-roles.sh` runs once). Regenerating a password afterwards makes the files and the database disagree; see [S0.14](#s014-troubleshooting).
- **Where:** [`scripts/dev_secrets.py`](../../scripts/dev_secrets.py), [`compose.dev.yaml`](../../compose.dev.yaml), [`.gitignore`](../../.gitignore).

### D0.3 Settings are loaded explicitly, never discovered

- **Decision:** the API never reads `.env` by itself. Development commands load it with `uv run --env-file .env …`. Tests run without it.
- **Why:** the test suite cannot pick up a developer's database by accident. The full reasoning is in [D2.2](02-configuration-and-persistence.md#d22-configuration-and-secrets-fail-closed).
- **Landmine:** settings *do* read real environment variables. If a `HUMANI_T_*` variable is set in your shell (for example after the tamper exercise in [04](04-audit-log.md)), `uv run pytest` builds some apps and every CLI test with it. Check with `Get-ChildItem Env:HUMANI_T_*` before running tests; it must print nothing.

### D0.4 A separate database for tests

- **Decision:** the init script creates `humani_t_test` next to `humani_t`, with the same roles and grants. The Postgres contract tests only ever use the URL in `TEST_DATABASE_URL`, which you point at `humani_t_test`.
- **Why:** contract tests delete what they write (`DELETE FROM users`, `sessions`, …). During the checkpoint work they once ran against the development database and wiped the development accounts.
- **Costs:** the test database must be migrated too ([S0.6](#s06-migrate-the-test-database)); audit events accumulate in it forever, because nothing — including the tests — may delete them.

### D0.5 Windows specifics

- `.gitattributes` stores text with LF line endings in the repository (`* text=auto eol=lf`), so Windows checkouts do not produce noisy diffs; `.bat`, `.cmd` and `.ps1` keep CRLF.
- Ports avoid common clashes: the API on 8731 (not 8000, which `mkdocs serve` uses, and Windows lets both bind it without an error — uvicorn reports healthy while the browser shows the docs site), Postgres on 55432 (so a Postgres already on 5432 is untouched), Valkey on 56379, Mailpit on 51025 and 58025, all bound to `127.0.0.1` only.
- Commands in the walkthroughs are PowerShell 5.1-compatible: no `&&`, no `export`.
- PowerShell 5.1 encodes text piped into a program with `$OutputEncoding`, which defaults to ASCII: a non-ASCII character in a password piped to `create-admin` arrives as `?`. Keep piped passwords ASCII, or first run `$OutputEncoding = New-Object System.Text.UTF8Encoding $false` in that shell. PowerShell also appends a line break; the CLI strips `\r\n`.

## Libraries

These are tools rather than Python packages. Python libraries are described in the phase that introduced them.

### Python 3.13

- **What it does:** the language version. Modern typing (`list[str]`, `X | None`, generic syntax `def f[T]()`), and every module starts with `from __future__ import annotations` (PEP 563), which lets a class reference itself in its own signatures without quotes.
- **Why this one:** the newest stable version when the project started; `services/api/.python-version` pins it.
- **Trade-offs:** some packages lag a new version; all of ours have wheels.

### uv

- **What it does:** Python package and project manager. Creates the virtual environment (`services/api/.venv`), resolves and locks dependencies (`uv.lock`), runs commands inside the environment (`uv run`), loads env files (`--env-file`), and can install Python itself.
- **Why this one:** very fast, reproducible (the lockfile pins every transitive version), one tool instead of pip + venv + pip-tools.
- **Trade-offs:** newer than pip; contributors must install it.
- **Note:** this machine's environment sits on Anaconda's Python 3.13 (tracebacks mention `anaconda3`). It works. `uv python install 3.13`, deleting `.venv`, then `uv sync --python-preference only-managed` makes it independent of Anaconda.

### Docker and Docker Compose

- **What it does:** containers for every backing service, described in one file, `compose.dev.yaml`, with passwords passed as secrets.
- **Why this one:** everyone runs the same Postgres, Valkey and Mailpit versions; the production deployment (M4) is Compose too.
- **Trade-offs:** Docker Desktop must be running; its volumes hold the development data (`docker compose -f compose.dev.yaml down -v` deletes it).

### Mailpit v1.27 (`axllent/mailpit`, development only)

- **What it does:** a fake mail server that accepts every message and shows it in a web inbox at http://127.0.0.1:58025. Nothing is delivered to real addresses.
- **Why this one:** small, single binary, a usable web UI; the API talks to it over plain SMTP exactly as it will talk to a real server.
- **What we gave up:** a TLS mail path in development; production uses the organisation's own SMTP server with STARTTLS (untested so far, gap G6 in [05](05-accounts-and-sessions.md#known-gaps)).

### Postman, pgAdmin 4, a browser

- **Postman** sends HTTP requests with full control over headers, cookies and bodies, and its Collection Runner repeats a request (used for throttling tests).
- **pgAdmin 4** is a database client: run SQL as a chosen role and look at rows, grants and constraints.
- **A browser** for Mailpit and for the development-only Swagger page at http://127.0.0.1:8731/docs.

### pnpm and Biome

Present at the repository root (`package.json`, `biome.json`) for the future web app. Described in [01](01-baseline-and-quality-gates.md#biome-2512-and-pnpm-1234).

### S0.9 Start the API

In a terminal you keep open, in `services\api`:

```powershell
uv run --env-file .env uvicorn app.main:app --reload --port 8731 --no-proxy-headers
```

Expect `Uvicorn running on http://127.0.0.1:8731`. Each request then appears as one uvicorn access line (client, method, path, status). Those lines do **not** carry the request id; the id is in the `x-request-id` response header, and on the application's own structured log lines (`storage_unavailable`, `email_delivery_failed`, …), which only appear for warnings and errors. `--reload` restarts on Python file changes, not on `.env` changes: restart by hand after editing `.env`. `--no-proxy-headers` stops uvicorn rewriting the client address from `X-Forwarded-For`; the API decides that itself, from `HUMANI_T_TRUSTED_PROXIES` ([05](05-accounts-and-sessions.md) D5.6).

### S0.10 Postman

1. Create a collection named `humani-t`, or import `http://127.0.0.1:8731/openapi.json` (Import → Link) to get every endpoint.
2. Collection → Variables: add `base` = `http://127.0.0.1:8731/api/v1`, plus empty `session` and `csrf`.
3. Collection → Headers (or on each request after login):
   - `Cookie` = `__Host-session={{session}}; __Host-csrf={{csrf}}`
   - `X-CSRF-Token` = `{{csrf}}`
4. On the **login** request and the **register** request, Scripts → Post-response (both start a session, so both must capture its cookies). The variables always hold the most recent session: after registering as someone else, sign in as the admin again to switch back. Also add the cookie-capture script to the Post-response tab of `POST {{base}}/account/password` and of `POST {{base}}/auth/reauthenticate`: a password change and a step-up both issue new cookies and revoke the old session.

```js
for (const h of pm.response.headers.all()) {
  if (h.key.toLowerCase() !== "set-cookie") continue;
  const [name, value] = h.value.split(";")[0].split("=");
  if (name === "__Host-session") pm.collectionVariables.set("session", value);
  if (name === "__Host-csrf") pm.collectionVariables.set("csrf", value);
}
```

Why the manual cookie header: the cookies are `Secure`, and over plain `http://` some clients will not send Secure cookies back automatically. Copying them into variables makes the tests independent of that behaviour. In production, everything is HTTPS. Tokens are URL-safe base64 and never contain `=`, so the `split("=")` above is safe.

For tests that need two signed-in devices at once ([T5.5](05-accounts-and-sessions.md#t55-sessions-on-several-devices)), duplicate the login request as `login (device B)` and change its script to save into `session_b` and `csrf_b`; a request sent "as device B" then uses `__Host-session={{session_b}}; __Host-csrf={{csrf_b}}` and `X-CSRF-Token: {{csrf_b}}` on the request itself, which overrides the collection header.

### S0.13a Without Docker: in-memory storage and the demo stand-ins

To click through the whole review flow (plan, run, screen, brief) with no Postgres, no Valkey, no Ollama and no internet. Everything lives in the API process's memory and is gone when it stops; never use it for real data. Production refuses every setting below.

- **The run worker runs inside the API** (`HUMANI_T_RUN_WORKER_IN_PROCESS`, on by default with in-memory storage), because a separate worker process would have its own, empty memory.
- **`HUMANI_T_DEMO_INFERENCE=true`** answers every model call with canned answers made by code. Its model id is `demo-stand-in (not a model)`, so every receipt, decision and manifest says so.
- **`HUMANI_T_PAPER_SOURCES=demo`** returns made-up "Demo paper n" records about your search terms: some without an abstract (skipped), some with a fake email and phone number (masked), some with only a DOI.
- **`HUMANI_T_DEV_ADMIN_EMAIL` and `HUMANI_T_DEV_ADMIN_PASSWORD`** create the first administrator at start, since `create-admin` cannot reach another process's memory.

In one PowerShell window (no `--env-file`, so no database URL is loaded; no `--reload`, which would wipe the memory on every save):

```powershell
cd services\api
Remove-Item Env:HUMANI_T_DATABASE_URL -ErrorAction SilentlyContinue
$env:HUMANI_T_ENVIRONMENT = 'development'
$env:HUMANI_T_PUBLIC_ORIGIN = 'http://localhost:5173'
$env:HUMANI_T_DEMO_INFERENCE = 'true'
$env:HUMANI_T_PAPER_SOURCES = 'demo'
$env:HUMANI_T_DEV_ADMIN_EMAIL = 'dev@example.org'
$env:HUMANI_T_DEV_ADMIN_PASSWORD = 'violet-harbour-quietly-41-lanterns'
uv run uvicorn app.main:app --port 8731 --no-proxy-headers
```

The log shows `demo_model_in_use`, `development_admin_created` and `worker_started_in_process`. In a second window, from the repository root:

```powershell
pnpm --filter @humani-t/web dev
```

Open `http://localhost:5173` (not `127.0.0.1`), sign in as `dev@example.org`, set up a second factor (an authenticator app or a passkey; it is lost when the API stops, so remove the old one from the app afterwards), then create a project, ask a question, choose Quick, accept the draft and start the run. To use your own Ollama instead of the demo model, leave out `HUMANI_T_DEMO_INFERENCE` and set `$env:HUMANI_T_INFERENCE_URL = 'http://127.0.0.1:11434'`.

### S0.13b Real mode on this machine: a real model and real paper sources

Everything goes in `services\api\.env`, which git ignores. Each line is read whenever a window starts the API or the worker.

- **Your own Ollama:** `HUMANI_T_INFERENCE_URL=http://127.0.0.1:11434` and `HUMANI_T_INFERENCE_MODEL=qwen3.5:9b`. On a laptop CPU, also set `HUMANI_T_SCREENING_CONCURRENCY=1` and `HUMANI_T_INFERENCE_TIMEOUT_SECONDS=900`. Ollama answers one request at a time, and a queued request's time limit runs while it waits.
- **A hosted model**, for fictional questions only ([ADR 0010](../adr/0010-openai-compatible-models-as-an-opt-in.md)):
  - `HUMANI_T_INFERENCE_API=openai`
  - `HUMANI_T_INFERENCE_URL=https://api.openai.com/v1`
  - `HUMANI_T_INFERENCE_MODEL=gpt-5-mini`
  - `HUMANI_T_INFERENCE_TOKEN=<key>`
  - `HUMANI_T_ALLOW_HOSTED_INFERENCE=true`
  - `HUMANI_T_INFERENCE_TIMEOUT_SECONDS=400` (a reasoning model sometimes takes minutes)
  - `HUMANI_T_SCREENING_CONCURRENCY=2` (more can hit the rate limit)
- **Paper sources:** `HUMANI_T_PAPER_SOURCES=openalex,europepmc,arxiv`. Empty searches nothing.
- **Geography:** `HUMANI_T_MASK_COUNTRIES_AND_REGIONS=false` keeps "the Sahel" or "Mali" in the question, so the search keeps them ([ADR 0011](../adr/0011-countries-and-regions-as-an-operator-setting.md)).

Do not type `$env:HUMANI_T_…` lines into a window for these. A setting typed into a window overrides `.env` until the window closes, and it reaches only programs started afterwards from that same window. Both have caused hard-to-see failures: a worker without paper sources, and an API still sending OpenAI-format requests to Ollama. To clear them, run `Remove-Item Env:HUMANI_T_* -ErrorAction SilentlyContinue`, or open a new window. The privacy receipt's "Sent to …" line shows which model was really used.

**If Valkey's port is refused on Windows:** Hyper-V can reserve port 56379 at boot (`netsh interface ipv4 show excludedportrange protocol=tcp`). Save this as `compose.valkey-port.local` (git ignores `*.local`):

```yaml
services:
  valkey:
    ports: !override
      - "127.0.0.1:6390:6379"
```

Start the services with `docker compose -f compose.dev.yaml -f compose.valkey-port.local up -d`, and change `:56379/` to `:6390/` in `HUMANI_T_VALKEY_URL` in `services\api\.env`.

### S0.14 Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `403 Cross-site requests are not allowed` from Swagger | `HUMANI_T_PUBLIC_ORIGIN` does not match the browser's address | Use exactly `http://127.0.0.1:8731` (not `localhost`) or change the setting to match |
| `403 Missing or invalid CSRF token` | Header missing, or `{{csrf}}` is from an older session | Sign in again so the script refreshes the variables |
| `401` right after signing in | Postman sent stale cookies | Check the `Cookie` header uses `{{session}}`; disable Postman's automatic cookie jar for the domain if it conflicts |
| `429` unexpectedly | Earlier failed attempts within 15 minutes | Wait for the `Retry-After` seconds, or sign in successfully once (it resets the account count) |
| `503` on every request | Postgres stopped, or the pool is exhausted | `docker compose -f compose.dev.yaml ps`; start Postgres |
| `503` with `Retry-After` on login | Valkey stopped: sign-in fails closed ([06](06-mfa.md), G1 closed) | `docker compose -f compose.dev.yaml start valkey` |
| `password authentication failed` (pgAdmin or the API) | Secret files regenerated after the volume was created | Dev only: `docker compose -f compose.dev.yaml down -v`, `docker compose -f compose.dev.yaml up -d`, re-run S0.5 to S0.7. **Deletes all dev data** |
| `alembic current` shows an older revision | Migrations not run | `uv run --env-file .env alembic upgrade head` |
| Postgres tests fail with `relation … does not exist` or a missing column | `humani_t_test` not migrated | Run [S0.6](#s06-migrate-the-test-database) |
| `set HUMANI_T_MIGRATION_DATABASE_URL to run migrations` | Alembic run without `--env-file` and without the variable | Add `--env-file .env`, or set the variable as in S0.6 |
| Tests fail with `database_url requires key_encryption_keys`, or a CLI test touches a real database | A `HUMANI_T_*` variable is set in the shell | `Get-ChildItem Env:HUMANI_T_*`, then `Remove-Item Env:<name>` for each |
| A commit is rejected by a hook | The hook found an issue or reformatted a file | Read the message; if it reformatted, `git add` the files again and re-run `git commit` |
| Emails don't arrive | Mailpit stopped, or `.env` lacks the SMTP lines | `docker compose -f compose.dev.yaml ps`; regenerate `.env` (move the old one aside, run `dev_secrets.py`) |
| uvicorn says healthy but the browser shows a documentation site | Something else holds the port (for example `mkdocs serve` on 8000) | Use port 8731 as above |
| `create-admin` refuses a password you typed correctly, or sign-in with it fails | Non-ASCII characters were turned into `?` by PowerShell 5.1's pipe encoding | Use an ASCII password, or set `$OutputEncoding` as in [D0.5](#d05-windows-specifics) |
| Tracebacks mention `anaconda3` | uv's environment is built on Anaconda's Python | Works; optionally `uv python install 3.13`, delete `.venv`, `uv sync --python-preference only-managed` |

## Glossary

| Term | Meaning |
| --- | --- |
| **Compose** | Docker Compose: one YAML file describing a set of containers, their ports, volumes and secrets. |
| **Docker secret** | A file mounted read-only at `/run/secrets/<name>` in a container; keeps passwords out of environment variables. |
| **Volume** | Docker-managed storage that outlives the container; `postgres-data` holds the development database. |
| **Loopback** | `127.0.0.1`: an address reachable only from the same machine. |
| **Lockfile** | `uv.lock`: the exact version of every dependency, direct and transitive, so every install is identical. |
| **Migration** | A versioned script that moves the database schema forward; Alembic records the current one in `alembic_version`. |
| **`.env` file** | A text file of `NAME=value` lines; loaded only when a command passes `--env-file .env`. |
| **Collection variable** | A Postman value (`{{base}}`, `{{session}}`) shared by every request in a collection. |
| **Health check** | A command Compose runs inside a container to decide whether it is `healthy`. |
